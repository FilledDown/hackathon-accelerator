# Pitch and Submission Templates

All claims must match `PROGRESS.md`. VERIFIED features may be described as working. PLANNED features go only under "What's next". SIMULATED features are described as mocked if they're mentioned at all.

## Narrative spine (pitch-director sets this first)
1. **Hook**: one specific person and their problem (5–10s).
2. **Problem**: why it matters, with one piece of evidence (10–15s).
3. **Solution in one sentence.**
4. **Live demo** of the core journey and the differentiator moment (60–70% of the time).
5. **How it works / the hard part**: architecture in one diagram, sponsor tech named (15–30s).
6. **Impact and what's next** (10–15s).
7. **Close**: the name plus the memorable line.

## 3-minute pitch timing
0:00 hook · 0:15 problem · 0:30 solution · 0:40 demo · 2:10 how it works · 2:40 impact/next · 2:55 close.
For a 5-minute pitch, scale the demo and the hard-part sections.

## Devpost (submission/DEVPOST.md)
Standard Devpost fields. Use the event's actual fields if they differ.
- **Inspiration**: a real story or observation. No generic "we noticed that..."
- **What it does**: the user journey in plain words, plus the differentiator.
- **How we built it**: stack, architecture, sponsor technologies (named, and what each does).
- **Challenges we ran into**: 2–3 real technical challenges and how you solved them. This is where depth becomes visible.
- **Accomplishments that we're proud of**: concrete and verifiable.
- **What we learned.**
- **What's next**: planned features go here, clearly as future work.
- **Built with**: tags.
- Links: repo, demo video, live URL (if deployed and stable).

## Slides (submission/SLIDES.md): 6–8 slides max
1. Title + one-line value proposition
2. Problem (person + evidence)
3. Solution (one sentence + a hero screenshot)
4. [LIVE DEMO] (this slide is just a cue)
5. How it works (diagram; sponsor tech highlighted)
6. Impact / traction / evidence
7. What's next + team
Write each slide as: title, ≤3 short lines, a visual description, speaker notes.

## Demo script (submission/DEMO_SCRIPT.md)
A table: `time | action (exact click/input) | what to say | fallback if it fails`. Include setup steps (reset script, pre-warm, demo data) before the table.

## Judge Q&A (inside PITCH.md)
At least 8 likely questions, each with a ≤30-second answer. Always include: "What happens when it fails?", "What did you build during the event?", "How is it different from <closest competitor>?", "Who's the first user?", "What was the hardest part?", plus one sponsor-specific question per targeted prize.

## README (submission/README.md, and copied to the repo root)
What it is (2 lines + screenshot) · Demo video link · Features (verified only) · Tech stack · Architecture diagram · Run it locally (copy-pasteable commands, env vars from .env.example) · Demo mode · Team · License.
